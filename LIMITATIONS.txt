DeepSeek 峰谷价状态插件 · 已知限制
包名：@local/dsh-peak-status
最后更新：2026-10-18

本文件只记录"当前版本确实做不到"或"有明确代价"的地方，不写使用说明（使用说明见 README.md）。

一、位置与外观
1. 胶囊在会话标题栏右侧，不居中。
   原因：宿主标题栏只提供两个可插入座位——conversation.header.leading（标题左侧）和
   conversation.session.header.utilities（标题右侧），没有中间插槽；且 conversation.session.header
   这一行没有 position 定位的祖先（实测 offsetParent 回退到 body），没有可做绝对居中的参照盒。
   唯一能真居中的办法是整行替换 conversation.session.header（single 槽、shadows-shipped-ui），
   需要重画标题、操作按钮、面包屑、工具区和角落控件，宿主改版即失效，代价不成比例。
2. 不能用窗口级 position: fixed 定位。实测会落进桌面端标题栏的拖拽区（-webkit-app-region: drag），
   那里收不到指针事件，双击会被系统解释成最大化/还原窗口。
3. 胶囊宽度约 470px（14px 字号），窄窗口下会挤压标题栏，标题可见部分变短。
   字号上限受标题栏那一行的高度限制：胶囊是行内元素（32px 高），行高撑不下时会挤动整个标题栏；
   当前没做过目视验证，32px 是在不测量行高的前提下取的安全值，再往上调（36px/15px、40px/16px）
   有把标题栏顶高的风险。
4. 没有会话打开时胶囊不显示（utilities 是 session 作用域的插槽）。
5. 页面视觉未在浏览器中实际截图验证（当前环境无浏览器控制）。已校验的只有：JavaScript 语法、
   插槽注册（active）、路由返回、宿主逻辑断言；观感、间距、深浅色主题下的效果均未目视确认。


二、峰谷判定
6. 法定节假日表只收录到 2026 年（2026-01-01 起各假期）。2027 年的《放假安排通知》截至
   2026-10-19 尚未由国务院办公厅公布，因此在公布前任何程序都不可能知道 2027 年放哪几天、
   哪天调休上班——万年历只能算出"春节是哪一天"，算不出"放哪几天"（这是行政决定，不是历法）。
   未收录年份的日期一律按普通工作日处理，可能把实际假期误判成峰价（显示峰价、峰价提醒、
   按峰价计价）。明细面板会显示"假期表未覆盖当前年份"提示，不会闷声当工作日算。
   修法：通知发布后把日期补进 index.js 顶部的 HOLIDAYS 集合（一行一个日期）。
   已知 2026 年数据核对过：中秋 9/25–27、国庆 10/1–7、调休 9/20 与 10/10 上班（官方说明
   调休上班的周末仍按谷价，故无需单独处理）。
7. 时区固定为 Asia/Shanghai（UTC+8），不跟随系统时区。跨时区使用时倒计时与相位仍按北京时间。
8. 只排除"法定节假日整天"；调休上班的周末按官方规则仍算谷价，插件没有单独处理调休日表。
9. 峰谷边界按分钟精度判定：09:00、12:00、14:00、18:00 整点切换，不支持秒级自定义。


三、余额
10. 余额来自 DeepSeek 平台账号（deepseekAccount 服务），需要应用内已登录 DeepSeek 账号。
    未登录显示「未登录」，账号服务缺失或请求失败显示「余额 --」。
11. 插件不读取 API Key，也不支持用 API Key 查余额；纯 API Key 使用方式下余额不可用。
12. 余额缓存 60 秒，刚扣费后最多有 1 分钟延迟。


四、Token 与费用
13. 费用是本地按官方公开价目估算，不是账单；最终以平台账单为准。
14. 价目表内置 deepseek-flash 与 deepseek-v4-pro（2026-10 人民币价目）。模型名含 "pro" 用 Pro 价目，
    其余一律按 Flash 价目估算；未知/新模型会在明细里以 pricedAs 标出用的是哪套价，但金额可能偏差。
15. 不含 Search / Fetch 按次计费（官方自 2026-11-01 00:00 起收费），也不含图片、附件等其他计费项。
16. Token 用量只能读当前进程内已打开（live）的会话。归档或未打开的会话读不到，
    胶囊费用显示「--」，明细显示「该会话不在当前进程中」。
17. 只累加 assistant/message 事件里的 usage。某次请求若没有上报 usage（中断、失败、重试），
    这次请求的 token 与费用不会被计入。
18. 缓存命中与输入的口径按"inputTokens 为未命中部分"解释（实测缓存命中量远大于输入，可反证）。
    合计显式写成 输入 + 缓存命中 + 输出；若宿主将来改变上报语义，这个口径需要复核。
19. 费用按每条请求发生时刻的相位分别计价，跨峰谷会话会拆成峰、谷两笔；若日志事件缺少时间戳，
    该条按当前时刻的相位计价。


五、提醒与暂停
20. 提醒只在"峰价 + 有会话正在运行"时出现，客户端每 5 秒轮询一次；短于 5 秒的一轮可能观察不到。
21. 每个峰价时段只弹一次：以"下次切换时刻"为块标识，用户点「知道了」后写入 localStorage
    （键名前缀 dsh.peak-status.reminded.），同一时段刷新页面也不会再弹。想让它重新弹，
    清掉这些键即可。若浏览器禁用了 localStorage，退化为"本次页面加载内只弹一次"。
    弹窗没有时限：不会自动消失，一直等到用户点「知道了」或进入谷价时段才收起，
    因此可能长时间盖在聊天区中央；没有"30 秒"过期机制，也没有自动关闭。
22. "暂停"不是系统级冻结：模型写完 HANDOFF.md 并结束本轮后，UI 标记为已暂停，
    但插件不会阻止后续工具调用或新一轮对话；用户发新消息即视为恢复。
23. 暂停标记是内存态，进程重启后丢失（会话日志里没有对应事件类型，无法持久化）。
24. 提醒里的"复制「暂停」"依赖浏览器剪贴板权限，失败时按钮不会报错，需要手动输入。
25. 收尾协议的可靠性依赖模型遵循系统提示词；插件没有强制手段（如工具守卫）保证一定写交接文档。


六、接口与安全
26. HTTP 路由 /peak-status/state 没有独立鉴权，只靠同源限制（Sec-Fetch-Site 非 same-origin/none 返回 403）
    且不下发 CORS 授权。同机的其它本地进程仍可直接请求该端口拿到余额与用量。
27. 路由返回值包含余额与 Token 用量，属于账户信息，不要转发或外泄。


七、运行与维护
28. 插件以 link 方式装在 desktop profile（源码目录直接挂载）。改宿主半（index.js）需要：
    插件管理里禁用再启用该插件行，或重启客户端；仅改文件不会热生效。
29. 改客户端半（client.js）需要刷新页面才会重新拉取模块；页面内不会自动热更新。
30. 插件对所有会话生效：系统提示词里会常驻一段「峰谷价收尾协议」（约 500 字），
    会占用每次请求的少量输入 token。
